# naive-connect

Подключение машины к существующему [NaiveProxy](https://github.com/klzgrad/naiveproxy) одной командой.

Скрипт ставит клиент `naive` как systemd-службу и поднимает два локальных входа:
SOCKS5 на `127.0.0.1:1080` и HTTP на `127.0.0.1:8080`. Прокси-сервер должен быть уже развёрнут.

## Подключение

```sh
bash <(curl -fsSL https://raw.githubusercontent.com/leontevewan/naive-connect/main/connect.sh)
```

Реквизиты можно задать двумя способами — ссылкой целиком:

```
naive+https://ЛОГИН:ПАРОЛЬ@домен:443
```

или по частям: нажмите Enter на вопросе про ссылку, и скрипт спросит домен, логин и пароль отдельно.

Без интерактива:

```sh
sudo bash connect.sh --link 'naive+https://ЛОГИН:ПАРОЛЬ@домен:443' --env
```

## Что делает

- определяет архитектуру и качает официальный клиент из релизов `klzgrad/naiveproxy`
- создаёт системного пользователя `naive` и конфиг `/etc/naive/config.json` с правами `640`
- регистрирует и запускает службу `naive-client`
- ставит себя как команду `naive-connect` для смены прокси и диагностики
- по флагу `--env` прописывает `http_proxy` и `https_proxy` в `/etc/environment`
- в конце сверяет внешний IP напрямую и через прокси и сообщает, работает ли туннель

Клиент работает под непривилегированным пользователем, root ему не нужен.

## Проверка

```sh
curl --socks5-hostname 127.0.0.1:1080 https://api.ipify.org
curl --proxy http://127.0.0.1:8080 https://api.ipify.org
```

Оба входа ведут в один процесс. HTTP нужен потому, что `apt`, `python-requests` и многое другое
не понимают `socks5://` в переменной `http_proxy`, а `http://` понимают все.
В конфиге naive поле `listen` принимает массив, так что это одна служба, а не две.

## Смена прокси

Когда прокси перестанет работать — заблокируют, кончится оплата, смените сервер, —
переустанавливать ничего не нужно. Скрипт при подключении кладёт себя в систему
как команду `naive-connect`:

```sh
sudo naive-connect switch
```

Спросит новые реквизиты (ссылкой или по частям), перепишет конфиг, перезапустит
службу и сразу проверит, что туннель поднялся. Локальные порты не меняются —
всё, что было настроено на `127.0.0.1:1080` и `:8080`, продолжит работать.

Можно и одной строкой, без вопросов:

```sh
sudo naive-connect switch 'naive+https://ЛОГИН:ПАРОЛЬ@новый-домен:443'
```

## Управление

```sh
sudo naive-connect status      # куда смотрит сейчас и жива ли служба
sudo naive-connect test        # проверить туннель
sudo naive-connect uninstall   # удалить всё

journalctl -u naive-client -f
```

## Ключи

| Флаг | Смысл |
|---|---|
| `--link` | ссылка `naive+https://...` целиком |
| `--domain`, `--user`, `--password`, `--port` | реквизиты по частям |
| `--socks-port`, `--http-port` | локальные порты, по умолчанию 1080 и 8080 |
| `--env` / `--no-env` | прописывать ли `http_proxy` в `/etc/environment` |
| `--uninstall` | удалить клиент, службу и конфиг |
| `switch`, `status`, `test`, `uninstall` | команды после установки |
| `-h`, `--help` | справка |

## Требования

Linux с systemd, root для подключения, архитектура x64, arm64, arm, x86 или riscv64.
Пакеты ставятся через `apt-get` или `dnf`.
